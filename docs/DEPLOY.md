# Деплой: FTP/SFTP/SSH

## Что уже работает

`tools/php-deploy` — самостоятельный бинарь (MIT), не требует Zed API.

- `status` — список серверов и resolved-путей;
- `check` — проверка локального корня и SSH-доступа;
- `sync` — выгрузка всех файлов, кроме исключений;
- `upload --file PATH` — один файл;
- `watch` — опрос файлов и автоматическая загрузка изменённых
  (это и есть upload-on-save: сохранил файл — через 1–2 с он на сервере);
- `--dry-run` — показать, что будет сделано;
- транспорты: `local` (для тестов и зеркал) и `sftp` (ssh-ключи/agent).

Проверено на `fixtures/deploy-test`:

- `sync` выгрузил 3 файла, `vendor/`, `.zed/` и `*.log` исключены;
- `watch` поймал изменение `src/index.php` и загрузил его;
- `check` для недоступного SFTP вернул внятную ошибку
  `Connection refused`, без зависания.

## Конфиг `.zed/deploy.json`

```json
{
  "default": "staging",
  "servers": [
    {
      "name": "staging",
      "protocol": "sftp",
      "host": "example.com",
      "port": 22,
      "user": "deploy",
      "local_root": ".",
      "remote_root": "/var/www/app",
      "exclude": ["vendor/", "node_modules/", ".git/", ".zed/", "*.log"],
      "upload_on_save": true
    }
  ]
}
```

`local_root` считается от корня проекта (родитель `.zed`).

## Запуск в Zed

Палитра команд → `task: spawn`:

- `deploy: check`
- `deploy: sync`
- `deploy: watch` — держать запущенным на время работы
- `deploy: upload current file`

`upload current file` берёт `$ZED_FILE`, поэтому можно повесить на клавишу.

## Безопасность

- Пароли не поддерживаются и не хранятся: только ssh-ключи и ssh-agent.
- В `.zed/deploy.json` не должно быть секретов.
- `sftp` запускается с `BatchMode=yes` и `ConnectTimeout=10`.
- Рекомендуется отдельный deploy-пользователь и `authorized_keys` с
  ограничениями.

## Ограничения текущей версии

- Нет удаления файлов на сервере при удалении локально (sync только добавляет
  и перезаписывает).
- Нет сравнения/диффа и разрешения конфликтов.
- Нет просмотра удалённых файлов и редактора на сервере.
- Нет отдельного окна настроек — только JSON-конфиг.
- `watch` работает опросом (1–2 с), а не через inotify/FSEvents.
- Одновременно активен один сервер (переключение через `--server`).

## Что нужно для панелей как в PhpStorm

1. **Remote-панель в правом доке**: список серверов, статус, кнопки
   Sync/Watch, дерево удалённых файлов через `sftp`-листинг.
2. **DB-панель в правом доке**: подключения, схема, грид, консоль
   (крейт `php_database`, `sqlx`).
3. **Окно настроек деплоя**: отдельный GPUI-модал или страница Settings UI;
   нужен patch ядра и формы.
4. **Интеграция с сохранением**: подписка на `BufferEvent::Saved` в форке
   вместо polling-демона.
5. **Rsync-транспорт** и delete-propagation с подтверждением.
